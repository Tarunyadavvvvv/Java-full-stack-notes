1. Java Core & OOP (1–20)

#PriProblem & approach / follow-ups
1★★★Explain the 4 pillars of OOP with real examples. Encapsulation (private + getters), Abstraction (interface), Inheritance (extends), Polymorphism (override/overload). Follow-up: give a code example of each; abstraction vs encapsulation difference.
2★★★== vs equals(); the equals/hashCode contract. == compares references (identity); equals compares logical value. If equals is true, hashCode must match. Follow-up: what breaks if you override equals but not hashCode? (HashMap lookups fail.)
3★★★Why is String immutable? String vs StringBuilder vs StringBuffer. Immutability → security, thread-safety, string-pool caching. Builder = mutable/unsynchronized; Buffer = synchronized. Follow-up: why concatenation in a loop is O(n²).
4★★★Abstract class vs Interface — when to use which? Abstract = shared state/partial impl, single inheritance ("is-a"); interface = capability/contract, multiple ("can-do"). Follow-up: default methods (Java 8); diamond problem resolution.
5★★★Overloading vs Overriding. Overload = same name/diff params, compile-time (static binding); override = same signature parent→child, runtime (dynamic dispatch via vtable). Follow-up: can you override static/private? (No — hidden.)
6★★Is Java pass-by-value or pass-by-reference? Always pass-by-value; for objects the reference value is copied (can mutate state, can't reassign caller's var). Follow-up: demonstrate with a swap method.
7★★final, finally, finalize. final = constant/non-overridable/non-extendable; finally = always-run cleanup; finalize = deprecated GC hook. Follow-up: can finally be skipped? (System.exit / JVM crash.)
8★★static keyword — variables, methods, blocks, nested classes. Belongs to class not instance; shared; can't access instance members or this. Follow-up: static block init order; why main is static.
9★★SOLID principles with examples. SRP, Open/Closed, Liskov, Interface Segregation, Dependency Inversion. Follow-up: show an OCP violation (big switch) & fix with polymorphism.
10★★Composition vs Inheritance — why "favour composition"? Inheritance = tight coupling, fragile base class; composition = flexible has-a, testable. Follow-up: a case where inheritance is right.
11★★Autoboxing/unboxing & the Integer cache. Auto conversion int↔Integer; cache -128..127 so == on small Integers is true but not large. Follow-up: always use equals for wrappers; NPE on unboxing null.
12★★Can you achieve multiple inheritance in Java? Not via classes (diamond problem); yes via multiple interfaces. Same default method → must override, use Interface.super.m().
13★★Method/field hiding vs overriding. Static methods & fields are hidden (resolved by reference type, static binding); instance methods are overridden (dynamic). Follow-up: trick output question.
14★★Marker, functional & sealed interfaces. Marker = no methods (Serializable); functional = 1 abstract method (lambda target); sealed (17) = restricts implementers. Follow-up: @FunctionalInterface.
15★★Records (Java 16) — what & why. Immutable data carriers; auto equals/hashCode/toString/accessors. Follow-up: records vs Lombok @Data; can records have methods?
16★Shallow vs deep copy; clone() pitfalls. Shallow shares nested refs; deep copies them. Follow-up: copy constructor / serialization for deep copy.
17★Object class methods. equals, hashCode, toString, getClass, clone, wait/notify. Follow-up: why wait/notify are on Object not Thread.
18★Generics & type erasure; PECS. Compile-time safety, erased at runtime. Producer-Extends, Consumer-Super. Follow-up: why no new T() / T[].
19★Immutable class design. final class, final private fields, no setters, defensive copies of mutable fields, init via constructor. Follow-up: why immutability aids concurrency.
20★var (10), text blocks (15), switch expressions, pattern matching (21). Local type inference; multiline strings; switch returns value + patterns. Follow-up: when var hurts readability.
Flagship deep-dive (Q2): The equals/hashCode contract is the #1 OOP gotcha. 
@Override public boolean equals(Object o){
  if(this==o) return true;
  if(!(o instanceof User u)) return false;
  return id==u.id && Objects.equals(email, u.email);
}
@Override public int hashCode(){ return Objects.hash(id, email); }
Break it → objects "lost" in HashMap/HashSet. Always override both, use the same fields in each.

2. Collections (21–31)

#PriProblem & approach / follow-ups
21★★★Internal working of HashMap (Java 8+). Array of buckets; index = (n-1)&hash; collisions chained, treeify to red-black tree at >8 (table≥64); load factor 0.75 → resize doubles. Follow-up: why capacity is a power of 2; why keys should be immutable.
22★★★ArrayList vs LinkedList. Array (O(1) get, O(n) mid-insert, grows ~50%) vs doubly-linked (O(1) insert with ref, O(n) get). Follow-up: which for a queue? When is LinkedList actually better? (rarely.)
23★★★HashMap vs ConcurrentHashMap vs Hashtable. Not thread-safe vs bin-level locking (CAS+synchronized) vs fully-synchronized legacy. Follow-up: why CHM doesn't allow null keys; segment evolution.
24★★HashMap vs LinkedHashMap vs TreeMap. No order / insertion(or access) order / sorted (red-black, O(log n)). Follow-up: LinkedHashMap access-order for LRU.
25★★fail-fast vs fail-safe iterators. modCount → ConcurrentModificationException vs snapshot/copy (CopyOnWrite, CHM). Follow-up: safely remove during iteration (Iterator.remove / removeIf).
26★★Comparable vs Comparator. compareTo (natural, in-class) vs compare (external, multiple orders). Follow-up: Comparator.comparing().thenComparing().reversed().
27★★Set implementations & how HashSet works. HashSet backed by HashMap; LinkedHashSet ordered; TreeSet sorted. Follow-up: dedup logic relies on equals/hashCode.
28★★How does HashMap resize & what's the cost? When size>cap×0.75, new array 2×, rehash entries. Follow-up: pre-size to avoid rehashing; amortized O(1).
29★★Queue/Deque: ArrayDeque vs LinkedList vs PriorityQueue vs Stack. Use ArrayDeque for stack/queue; PriorityQueue = heap. Follow-up: why avoid legacy Stack/Vector.
30★BlockingQueue & producer-consumer. ArrayBlockingQueue/LinkedBlockingQueue; put/take block. Follow-up: bounded vs unbounded; back-pressure.
31★Iterator vs ListIterator vs Enumeration; Collections.unmodifiable/synchronized. Bidirectional, legacy, wrappers. Follow-up: immutable List.of vs unmodifiableList.

3. Exception Handling (32–36)

#PriProblem & approach / follow-ups
32★★★Checked vs unchecked exceptions; the hierarchy. Throwable→Error/Exception; checked = compile-time recoverable (IOException), unchecked = RuntimeException (bugs). Follow-up: why not catch Error/Throwable.
33★★★try-with-resources & finally semantics. Auto-closes AutoCloseable in reverse order; suppressed exceptions. Follow-up: exception in both try & finally — which wins?
34★★throw vs throws; custom exceptions; wrapping with cause. throw=instance, throws=declaration. Always preserve cause. Follow-up: domain exception design.
35★★Common mistakes in exception handling. Swallowing, catching broad Exception, return in finally, logging+rethrowing both, exceptions for control flow. Follow-up: fail-fast.
36★★Global exception handling in Spring. @RestControllerAdvice + @ExceptionHandler → consistent error schema; ProblemDetail (RFC 7807). Follow-up: handling validation errors.

4. Multithreading & Concurrency (37–52)

#PriProblem & approach / follow-ups
37★★★Process vs thread; ways to create threads. Own memory vs shared heap+own stack. Thread/Runnable/Callable+Future. Follow-up: start() vs run(); why Runnable preferred.
38★★★synchronized vs volatile vs Atomic. Mutual exclusion+visibility vs visibility-only (not atomic i++) vs lock-free CAS. Follow-up: why volatile fails for counters.
39★★★Deadlock — causes, detection, prevention. 4 Coffman conditions; break circular wait via lock ordering / tryLock timeout. Follow-up: detect with jstack thread dump.
40★★★ExecutorService & thread pools. Reuse threads; fixed/cached/scheduled; core/max/queue/rejection. Follow-up: why prefer custom ThreadPoolExecutor over Executors factories.
41★★★Java Memory Model: happens-before & visibility. Without sync, threads may see stale cached values; synchronized/volatile establish happens-before. Follow-up: double-checked locking needs volatile.
42★★Thread lifecycle & states. NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED. Follow-up: wait vs sleep vs join.
43★★wait/notify/notifyAll; why on Object; spurious wakeups. Must hold monitor; loop on condition. Follow-up: notify vs notifyAll.
44★★ReentrantLock vs synchronized; ReadWriteLock. tryLock/timeout/fairness/interruptible; many readers OR one writer. Follow-up: always unlock in finally.
45★★CompletableFuture & async composition. supplyAsync/thenApply/thenCompose/thenCombine; non-blocking. Follow-up: exceptionally/handle; custom executor.
46★★CountDownLatch vs CyclicBarrier vs Semaphore. Wait-for-N (one-shot) / threads-wait-each-other (reusable) / permit-limited access. Follow-up: a use case for each.
47★★ConcurrentHashMap internals. Java 8: per-bin CAS+synchronized, no global lock; concurrent reads. Follow-up: vs Collections.synchronizedMap.
48★★ThreadLocal — use & leak risk. Per-thread value; leaks in pools → always remove(). Follow-up: use in request-scoped context.
49★★Producer-consumer implementation. BlockingQueue or wait/notify with bounded buffer. Follow-up: handle shutdown/poison pill.
50★★Race condition & how to fix a non-thread-safe counter. read-modify-write interleaving; fix with AtomicInteger/lock/synchronized. Follow-up: show the bug.
51★Virtual threads (Java 21, Loom). Lightweight JVM-scheduled threads; millions; great for blocking I/O. Follow-up: vs reactive; pinning.
52★Fork/Join & parallel streams. Work-stealing common pool, divide-and-conquer. Follow-up: when parallelStream hurts (small data, I/O, shared state).
Flagship (Q39): explain a deadlock & fix it. 
// Two threads lock A,B in opposite order -> deadlock
T1: synchronized(A){ synchronized(B){...} }
T2: synchronized(B){ synchronized(A){...} }
// FIX: global lock ordering (always A before B) OR tryLock with timeout + backoff
Interviewers love the follow-up "how would you detect it in prod?" → thread dump (jstack) shows "Found one Java-level deadlock".

Flagship (Q81/Q82): the self-invocation trap. 
@Service class OrderService {
  @Transactional public void outer(){ inner(); }   // inner's @Transactional is IGNORED
  @Transactional public void inner(){ ... }          // bypassed: same-object call skips the proxy
}
Fix: move inner() to another bean, or self-inject the proxy. This single concept explains most "my @Transactional/@Async/@Cacheable isn't working" bugs — a top product-company favourite.

Interview Strategy & Final Tips

How to crack the interview, not just the question:
  • Clarify before answering — restate the question, ask about scope/constraints. Interviewers reward this.
  • State the trade-off — "X improves throughput at the cost of consistency." There's rarely one right answer; reasoning wins.
  • Go breadth-first, then depth — give the headline answer, then offer to go deeper. Don't ramble.
  • Tie to a real example — pair every concept with where you'd use it / a framework that does it.
  • Think out loud & draw — especially for LLD/HLD; structure the answer as a flow.
  • Admit unknowns & reason — "I'm not sure, but I'd reason it as..." beats bluffing.
Suggested study order: Master all ★★★ first (the "almost-always-asked" core), then ★★, then ★. Within each topic the list runs beginner→advanced. Use this as a checklist — tick each problem when you can answer it and its follow-up out loud. Pair with the companion deep-dive PDFs for any topic you're shaky on.
The 80/20: if time is short, the highest-ROI must-knows are — equals/hashCode, HashMap internals, synchronized/volatile/Atomic, deadlock, thread pools, GC & memory leaks, Streams+Optional, Singleton/Strategy/State, DI & bean lifecycle, @Transactional self-invocation, N+1, REST design, ACID/isolation/indexing, joins & 2nd-highest-salary, CAP, idempotency, circuit breaker, URL shortener & rate limiter design, Kafka delivery semantics, caching+invalidation, container vs VM, K8s core objects, OAuth2/OIDC/JWT, and merge-vs-rebase + CI/CD flow.
